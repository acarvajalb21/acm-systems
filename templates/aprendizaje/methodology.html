  • Límite conocido. Una semana que agotó existencias pero tuvo salidas se toma como observada, aunque su consumo pudo quedar recortado.

3. Diseño de validación

Separación temporal por referencia; nunca se barajan las semanas.

  • Origen móvil. En cada origen el pronóstico usa solo las semanas anteriores; lo posterior no interviene. Una prueba automática altera el futuro y comprueba que el pronóstico no cambia.
  • Selección. El método de cada referencia se elige por menor error absoluto medio en la ventana de selección (hasta {{ k.select_max }} semanas antes de la prueba). En empate gana el más simple.
  • Prueba final. Las últimas {{ k.test }} semanas utilizables no se miran al elegir. El error que se muestra como desempeño es el de esa ventana, con su número de pronósticos.
  • Horizonte de la decisión. Se evalúa a una semana y también el acumulado de H semanas, con H = techo((tiempo de entrega + revisión) / 7), porque el punto de pedido depende del consumo de todo ese periodo. La elección usa el horizonte H si hay al menos {{ k.min_select }} pronósticos de selección; si no, el de una semana.{% if horizons %} Hoy: {% for h, n in horizons %}{{ n }} referencia{{ n|pluralize }} con H = {{ h }}{% if not forloop.last %}, {% endif %}{% endfor %}.{% endif %}
  • Historial corto. Con menos de {{ k.full_weeks }} semanas la prueba se reduce a {{ k.test_reduced }}; con menos de {{ k.min_weeks }} no se elige ni se prueba: se usa el promedio como respaldo y se marca «historial insuficiente». Hoy: {{ reduced }} referencia{{ reduced|pluralize }} con ventanas reducidas y {{ short }} con historial insuficiente.
  • Modelo entrenado sin fuga. Los coeficientes ridge que pronostican un origen se ajustan solo con filas, de cualquier referencia, cuya ventana objetivo terminó antes de ese origen. Rasgos: rezagos 1 a 4, medias de 4, 8 y 13 semanas, misma semana del año anterior (con indicador de existencia), seno y coseno de la época del año y proporción de semanas en cero; todo escalado por la media de la referencia hasta el origen. Penalización fija ({{ k.ridge_lambda }}) y tope fijo de valores escalados ({{ k.ridge_cap }}): no se ajustan con los datos.
  • Dependencia. Los pronósticos acumulados de orígenes consecutivos se solapan. Los «n» son conteos de pronósticos, no tamaños de muestra independientes.

Si una referencia no se puede calcular, queda marcada como «no calculable» con su motivo y las demás se calculan igual.
  • Cantidad. Lleva la posición al nivel objetivo, redondeada al empaque de compra y limitada por lo que alcanza a usarse antes del vencimiento (margen de {{ params.margen_vencimiento_dias }} días).

9. Límites y reproducibilidad

  • Datos sintéticos. El escenario se genera con reglas conocidas; un buen resultado aquí no anticipa el desempeño con datos de una operación real.
  • Pocas observaciones por referencia. Ventanas de {{ k.test }} semanas dan estimaciones ruidosas; por eso las cifras van con su «n» y se suman entre referencias.
  • Sin costos de faltante ni de mantener inventario. El nivel de servicio se fija como supuesto; no se optimiza un costo total.
  • Reproducible. Todo es Python puro y determinista: mismos datos, mismos resultados. Los hiperparámetros son fijos y están en el código (módulos series, reposicion, pagos y cobranza de la aplicación «aprendizaje»); las propiedades descritas aquí se comprueban con sus pruebas automáticas.
